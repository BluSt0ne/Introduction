# Project Archive · WOP & WW

World of Plant와 Wordless Mage를 소개하는 면접관용 프로젝트 아카이브입니다.

## 화면 구성

두 프로젝트 모두 어두운 바탕을 사용하며, World of Plant는 식물의 녹색, Wordless Mage는 마법과 황동의 색으로 구분합니다. 기본 화면은 두 프로젝트를 고르는 간결한 갤러리입니다.

- 프로젝트별 한 페이지: 컨셉 → 플레이 흐름 → 제작 방식 → 관련 기획서
- 상세 문서: 팝업 열람과 개별 페이지 링크
- 문서 목록: 프로젝트별로 종합·시스템·콘텐츠 분류, 대표 이미지와 주제별 픽토그램 표시
- 내부 관리: 리소스 출처·버전·이용 조건과 변경 기록을 편집 도구에서 관리하며 방문자 메뉴에서는 제외
- 기록 관리: 브라우저 로컬 초안, 가져오기, 데이터 파일 내보내기

현재 문서 34개와 중복을 제외한 문서 이미지 14개를 수록했습니다. 게임의 배포 이력이나 개인 담당 범위는 추정해서 넣지 않았습니다. 사이트의 v0.1.0은 아카이브 버전입니다.

## GitHub Pages 배포

배포 저장소: https://github.com/BluSt0ne/Introduction

1. 저장소 Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 선택합니다.
2. main 브랜치에 파일을 올리면 `.github/workflows/pages.yml`이 `public/`을 배포합니다.
3. Actions에서 성공 여부를 확인합니다. 배포 주소는 `https://blust0ne.github.io/Introduction/`입니다.

프로젝트 저장소이므로 주소에 `Introduction/` 경로가 포함됩니다. 루트 경로가 바뀌어도 동작하도록 사이트 파일 링크를 상대 경로로 작성했습니다.

워크플로는 GitHub 공식 문서의 Pages 구성을 따릅니다: [Using custom workflows with GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## 변경 기록·리소스 추가

1. 공개 사이트 주소 뒤에 `editor.html`을 붙여 기록 관리 화면을 엽니다. 방문자용 메뉴에는 관리 링크가 없습니다.
2. 변경 기록 또는 리소스를 작성해 **초안에 추가**를 누릅니다.
3. **초안 미리보기**에서 내용을 확인합니다. 초안은 현재 브라우저에만 저장됩니다.
4. **데이터 파일 내려받기**로 `site-data.js`를 저장합니다.
5. 저장소 `public/data/site-data.js`를 새 파일로 교체한 후 커밋합니다.
6. 배포가 완료되면 모든 방문자에게 변경 사항이 보입니다.

리소스에 로컬 파일을 연결했다면 해당 파일도 `public/assets/`에 추가합니다. 외부 URL은 전체 주소를 입력할 수 있습니다. 파일을 저장했다고 사이트에 업로드되지는 않으며, 공개 반영은 저장소 커밋을 통해 이뤄집니다.

기존 데이터 파일은 실행하지 않고 JSON 부분만 파싱해 가져옵니다. 초기화는 브라우저의 초안만 되돌리며, 공개 데이터는 변경하지 않습니다.

## 프로젝트 소개 수정

- 프로젝트 한 줄 소개, 썸네일: `public/data/site-data.js`의 `projects`
- 컨셉·플레이 흐름·제작 방식: `public/data/site-data.js`의 프로젝트별 `brief`
- 기획 문서와 리소스, 변경 기록: `public/data/site-data.js`
- 레이아웃과 반응형 스타일: `public/styles.css`

기획서 원본은 `public/downloads/`, 문서에 포함된 이미지는 `public/assets/media/`에 있습니다. 공개 화면에는 원본 다운로드 버튼을 표시하지 않습니다. 리소스의 미기록 항목(출처·이용 조건·버전)은 실제 정보를 확인해 보완합니다. 문서 텍스트는 웹 열람을 위해 추출한 데이터입니다.

## 로컬 실행·검증

별도 설치나 빌드가 필요하지 않습니다. Node.js로 실행합니다.

```sh
node scripts/serve.mjs
```

브라우저에서 http://127.0.0.1:4173 을 엽니다. `public/index.html`을 직접 열어 읽는 것도 가능하지만 초안 저장·복사 기능은 HTTP 미리보기를 권장합니다.

```sh
node --check public/app.js
node --check public/editor.js
node scripts/test.mjs
```

Google Fonts가 연결되지 않아도 시스템 폰트로 표시됩니다. 모든 문서·이미지 파일은 저장소에 함께 포함됩니다.

배포할 때 CSS·스크립트·데이터 파일 주소에 버전이 자동으로 붙어 이전 캐시가 남지 않도록 구성했습니다. 이전 로컬 미리보기(127.0.0.1)가 아니라 위의 공개 주소를 공유합니다.


## 사이트 편집 도구

공개 메뉴에는 편집 링크를 표시하지 않습니다. [사이트 편집](https://blust0ne.github.io/Introduction/editor.html) 주소로 직접 엽니다.

- 프로젝트: 홈 카드 제목·설명, 큰 제목, 컨셉·특징·플레이 흐름·제작 방식, 대표 이미지
- 문서: 제목·분류, 각 페이지의 문단·표 셀 수정과 문단 추가·삭제
- 리소스·변경 기록: 기존 항목 선택·수정 또는 새 항목 추가
- 내부 파일: HTML·CSS·스크립트를 직접 편집해 수정 파일에 포함
- 데이터: 기존 데이터 파일 가져오기, 초안 초기화, 데이터만 내려받기

### 로컬 저장소에 저장

Chrome 또는 Edge에서 편집 도구를 열고 **폴더 연결**로 이 저장소 폴더(또는 `public` 폴더)를 선택합니다. **폴더에 저장**을 누르면 데이터·추가 이미지·편집한 내부 파일을 씁니다. 기존 파일은 `public/.archive-backups`에 백업하고 이 폴더는 Git에서 제외합니다.

폴더 저장을 지원하지 않는 브라우저에서는 **수정 파일 내려받기**를 사용합니다. `site-edits.zip`에는 `public/` 경로 아래에 교체할 파일만 들어갑니다. 저장소 폴더에 압축을 풀고 변경을 확인한 뒤 커밋합니다.

이미지는 편집 도구에서 선택하면 브라우저에 보관하며 초안 미리보기에도 표시됩니다. 폴더 저장·내려받기 전에는 공개 파일이 되지 않습니다. 문서 편집은 웹 본문 데이터를 바꾸며 기존 문서 원본을 변환하지 않습니다. 사이트 글자는 `public/data/site-data.js`의 프로젝트별 `brief`에서 관리합니다.

구현 참고: [폴더 선택](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker), [파일 쓰기](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemFileHandle/createWritable).

### 실시간 미리보기와 이미지 배치

오른쪽 미리보기는 입력 중인 글자와 이미지 설정을 저장 전에도 보여 줍니다. 홈·선택한 프로젝트·선택한 문서·문서 목록을 고르고, 모바일 390px 또는 패널 너비로 확인합니다. **크게 보기**는 미리보기 영역을 넓히며 Escape로 돌아옵니다.

문서 탭에서 대표 이미지를 첨부하거나 본문에 PNG·JPEG·WebP 이미지를 추가할 수 있습니다. 기존 파일 경로나 외부 이미지 주소로도 추가합니다. 본문 이미지는 편집 영역에서 끌어 가로 위치와 위 여백을 바꾸고, 오른쪽 아래 손잡이로 너비를 조절합니다. 숫자 입력으로 너비·높이·여백을 지정하고 왼쪽·가운데·오른쪽 정렬, 전체 보이기·영역 채우기, 대체 텍스트와 설명을 설정합니다. 높이 0은 원본 비율을 유지합니다.

**위로·아래로**로 문단·표·이미지 순서를 바꿉니다. **본문 초안 저장**은 이미지 배치를 포함해 보관합니다. 프로젝트 이미지에는 맞춤 방식·가로·세로 초점·프로젝트 화면 너비 조절을 제공합니다. 반영 절차는 기존과 같이 초안 저장 → 폴더 저장 또는 수정 파일 내려받기 → 커밋·푸시입니다. 내부 CSS 파일은 **파일 초안 저장** 후 미리보기에 적용되며 HTML·스크립트의 변경은 파일을 실제 반영한 후 확인합니다.
