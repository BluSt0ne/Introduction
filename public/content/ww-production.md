# Wordless Mage 제작 과정

## 1. 마법으로 환경을 바꾸는 규칙 정하기

조작만으로 길을 통과하기보다 어떤 대상에 어떤 마법을 사용할지 생각하는 퍼즐을 설계했습니다. 마법과 대상의 관계를 이해하면 같은 규칙을 새로운 공간과 장치의 조합에 적용할 수 있는 구조입니다.

### 직접 정한 것

- 마법과 대상의 상호작용, 레벨의 핵심 규칙.
- 플레이어가 규칙을 익히는 순서와 퍼즐의 동선.
- 체력, 마법과 도전 조건을 포함한 데이터·밸런스.

### 화면에서 전달할 내용

현재 사용할 수 있는 마법, 선택한 대상과 예상 결과를 읽을 수 있어야 합니다. 플레이어가 시도한 행동의 성공과 실패도 이해할 수 있어야 합니다.

## 2. 레벨의 동선과 장치 배치하기

레벨디자인은 직접 맡았습니다. 지형, 로봇과 장치의 위치를 정하고, 이동하면서 관찰한 정보를 퍼즐 해결에 사용할 수 있는지 플레이로 확인했습니다.

### 배치할 때 보는 질문

- 현재 공간에서 무엇을 관찰하게 할 것인가.
- 사용할 수 있는 마법과 대상의 관계를 알아볼 수 있는가.
- 다음 발판이나 장치가 플레이어의 시야와 동선에 들어오는가.
- 실패 후 무엇을 달리 시도할지 생각할 여지가 있는가.

첫 레벨에는 이동과 점프 키 안내가 있습니다. 조작을 익히는 구간과 환경 규칙을 이해하는 구간을 함께 보며 플레이 흐름을 조정합니다.

## 3. 조준 안내와 실제 판정 맞추기

화면에서 가능해 보인 행동이 실제로는 다른 결과를 내면 플레이어가 규칙을 신뢰하기 어렵습니다. 현재 게임은 대상 판정, 조준선과 투사체 이동에 공통 장애물 판정 구조를 사용합니다.

### 구현에서 확인하는 조건

| 상황 | 의도한 동작 |
| --- | --- |
| 대상 앞에 벽이 있음 | 조준 안내와 투사체가 벽에서 끝남 |
| 벽 뒤에 대상이 있음 | 벽을 통과해 마법이 적용되지 않음 |
| 트리거 또는 대상 자신의 충돌체 | 가로막는 벽으로 오인하지 않음 |
| 컨베이어 조준 | 별도 조준 지점으로 바닥과 실제 장애물을 구분함 |

구현과 수정은 AI의 지원을 받되, 플레이어가 예상한 결과와 실제 결과가 일치하는지 직접 확인하는 관점으로 접근했습니다.

## 4. 레벨 선택과 재도전 흐름 연결하기

현재 게임은 지도에서 레벨 선택 → 플레이 → 결과 확인 → 다음 레벨 또는 재도전으로 이어집니다. 컷신은 지도에서 따로 볼 수 있어 플레이와 재도전은 바로 시작할 수 있습니다.

### 시도와 진행 기록을 나누기

다시 입장하면 지형·로봇·장치·체력·마법과 시도 중 기록을 초기화합니다. 클리어와 별 달성 기록은 별도로 보존합니다. 다음 레벨 해금과 추가 별 도전을 구분해 진행 목표와 재도전 목표를 나눕니다.

### 화면 연결에서 보는 것

- 다음에 도전할 레벨과 잠금 상태가 구분되는가.
- 재도전할 때 이전 시도의 상태가 남아 혼란을 주지 않는가.
- 결과 화면에서 달성한 조건을 확인할 수 있는가.
- 컷신을 보거나 건너뛰어도 의도한 화면으로 돌아오는가.

## 5. 아트와 효과음으로 결과 전달하기

아트는 직접 선정했습니다. 배경의 분위기와 함께 대상·장치·마법이 게임 안에서 구분되는지를 봅니다. 시각적 통일감과 기능 전달을 함께 확인하는 작업입니다.

효과음 제작에는 ElevenLabs Sounds를 활용했습니다. 소리는 분위기를 만드는 역할과 함께 플레이어가 행동의 결과를 확인하는 역할을 갖습니다.

### 게임 안에서 검수하는 기준

- 조작 중 자주 듣는 소리가 반복 청취에 부담스럽지 않은가.
- 입력, 마법 적용과 결과 확정의 소리가 서로 구분되는가.
- 화면의 피드백과 소리의 타이밍이 연결되는가.
- 배경과 효과음이 겹쳐도 필요한 정보를 알아들을 수 있는가.

## 6. 직접 플레이와 자동 검증 함께 보기

플레이 테스트와 수정 방향 결정은 직접 맡았습니다. 조작감, 동선, 퍼즐 전달과 난이도는 실제 플레이를 통해 확인했습니다.

현재 프로젝트에는 독립 레벨 생성, 순차 해금, 재도전 초기화, 별 조건과 연출, 컷신 복귀 등을 확인하는 검증 기능도 있습니다. 2026년 11월 24일에는 이 기능으로 최신 조작 화면과 지도·결과 UI를 새로 캡처했습니다.

### 서로 다른 확인 방법

| 방법 | 확인하는 것 |
| --- | --- |
| 자동 검증 | 정해진 조건과 상태 변화의 일관성 |
| 직접 플레이 | 조작감, 이해하기 쉬운 규칙, 퍼즐 동선과 체감 난이도 |
| 이미지 확인 | 실제 화면의 구성, 안내와 피드백 |

자동 검증은 분리된 테스트 진행도를 사용합니다. 갤러리의 결과 화면은 UI 확인용 장면이며 실제 플레이 성적이 아닙니다.

## 7. 관찰한 내용을 다음 수정으로 연결하기

플레이 중의 관찰을 수치, 배치, 판정과 피드백으로 나누어 수정 방향을 정합니다. AI에는 변경할 조건과 확인할 결과를 요청하고, 수정 뒤 다시 플레이하며 의도와 맞는지 판단합니다.

### 작업을 이어 가는 순서

1. 어떤 상황에서 무엇이 보였는지 기록합니다.
2. 플레이어에게 전달하려던 경험과 비교합니다.
3. 데이터·밸런스·레벨 또는 피드백 중 바꿀 대상을 정합니다.
4. 구현 조건과 완료 기준을 프롬프트로 전달합니다.
5. 결과를 직접 플레이하고 다음 수정 여부를 결정합니다.

게임 컨셉, 핵심 규칙, 레벨과 최종 판단은 직접 맡고, AI를 실제 결과물을 만드는 과정에 활용했습니다.
