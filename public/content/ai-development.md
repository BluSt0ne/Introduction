# AI를 활용한 게임 제작

규칙을 정하고, AI로 구현하고, 플레이로 다듬습니다.

## 한눈에 보기

### 어떤 일을 직접 했는가

게임 컨셉·핵심 규칙 결정, 프롬프트 작성, 플레이 테스트, 데이터·밸런스 조정, 레벨디자인, 아트 선정은 모두 직접 담당했습니다. AI에는 정해진 요구사항에 맞는 구현과 수정 작업을 요청했습니다.

| 직접 맡은 일 | 작업에서 정한 것 |
| --- | --- |
| 컨셉·핵심 규칙 | 플레이어가 반복할 행동과 그 행동이 만드는 재미 |
| 프롬프트 작성 | 구현할 동작, 제약 조건, 확인할 결과 |
| 플레이 테스트 | 조작감, 진행 흐름, 규칙 전달과 예외 상황 |
| 데이터·밸런스 | 비용·보상·효과·도전 조건의 조정 방향 |
| 레벨디자인 | 공간 배치, 동선, 장치의 조합과 학습 순서 |
| 아트 선정 | 게임의 분위기와 기능 전달에 맞는 리소스 선택 |

### 사용한 도구

| 도구 | 활용 범위 | 직접 맡은 판단 |
| --- | --- | --- |
| ChatGPT | 요구사항 구체화, 기획 문서와 포트폴리오 구성 정리 | 규칙의 채택 여부와 최종 문서 내용 |
| Claude | 요구사항에 따른 코드 구현과 수정 지원 | 구현 방향, 우선순위, 플레이 후 수정 지시 |
| ElevenLabs Sounds | 게임 효과음 제작 | 필요한 소리의 용도와 게임 안에서의 적합성 |

### 두 프로젝트에서 보여 주는 것

- World of Plant: 식물 생산, 장치와 자동화, 공간 확장을 하나의 성장 흐름으로 연결한 규칙 설계.
- Wordless Mage: 마법과 환경의 상호작용을 플레이어가 읽고 풀어 가도록 만든 퍼즐과 레벨 설계.
- 공통 제작 방식: 의도를 먼저 정하고, AI에 작업 조건을 전달한 뒤, 실제 플레이 결과로 수정 방향을 결정하는 과정.

넷마블 AI 인턴십 지원에서는 도구 이름을 나열하는 데서 그치지 않고, 무엇을 직접 설계했고 어떤 기준으로 결과를 확인했는지 두 게임을 통해 설명하고자 합니다.

### 컨셉과 플레이 흐름

식물에서 자원을 얻고, 장치와 업그레이드로 생산 구조를 키우며, 새로운 공간과 행성으로 정원을 넓히는 증분형 경영·자동화 게임입니다.

플레이어의 행동은 식물 배치와 생산 → 자원 확보 → 장치·업그레이드 투자 → 공간 확장 → 생산 구조 재구성으로 이어집니다. 단순히 수치가 오르는 것과 함께, 직접 만든 정원이 생산 체계로 바뀌는 모습을 보여 줍니다.

### 직접 설계한 범위

- 식물, 장치, 자원과 확장 기능이 연결되는 핵심 규칙을 정했습니다.
- 생산·설치·업그레이드에 쓰이는 데이터와 밸런스를 조정했습니다.
- 배치 공간과 확장 흐름을 설계하고, 실제 플레이를 통해 확인했습니다.
- 화면의 분위기와 기능 전달에 맞는 아트를 선정했습니다.
- 구현 요청과 수정 방향을 프롬프트로 작성했습니다.

### AI에 맡긴 작업과 직접 내린 판단

| 구분 | 역할 |
| --- | --- |
| 직접 결정 | 어떤 행동이 생산으로 이어지는지, 자동화와 확장이 언제 의미를 갖는지 |
| AI 작업 | 요구사항에 맞는 기능 구현과 수정 지원 |
| 직접 검수 | 배치와 생산이 의도대로 연결되는지, 성장 흐름이 끊기지 않는지 플레이로 확인 |
| 수정 판단 | 플레이 결과를 보고 데이터·밸런스·공간 구성을 바꿀 방향 결정 |

### 구현에서 확인할 수 있는 사례: 확장과 설치

현재 프로젝트에는 다른 행성으로 화물과 블루프린트를 보내고, 도착 뒤 설치를 진행하는 구조가 있습니다. 확장은 단순한 화면 이동을 넘어 생산 구조를 다른 공간으로 이어 가는 기능입니다.

이 기능을 설명할 때는 정상 도착 화면과 함께 에너지 부족, 설치 대기, 재화 처리 같은 예외 조건을 보여 줄 수 있습니다. 프로젝트에는 로켓 착륙과 설치 상태를 확인하는 별도 회귀 검사 항목도 마련되어 있습니다.

### 플레이에서 확인하는 기준

- 식물과 장치가 놓인 위치를 읽고 다음 행동을 선택할 수 있는가.
- 비용을 지불한 뒤 예상한 생산·설치 결과가 발생하는가.
- 업그레이드와 확장이 다음 목표로 자연스럽게 이어지는가.
- 자원 부족과 설치 불가 상태에서 이유를 파악할 수 있는가.
- 반복 배치와 확장 과정에서도 조작과 화면 확인이 부담스럽지 않은가.

## Wordless Mage

![Wordless Mage의 이동과 점프 안내 화면](assets/screenshots/2026-11-24/ww-controls.webp)

### 컨셉과 플레이 흐름

마법으로 환경의 규칙을 바꾸며 길을 찾는 퍼즐 게임입니다. 조작 자체와 함께 어떤 대상에 어떤 마법을 사용할지 판단하는 과정이 중심입니다.

현재 게임은 지도에서 레벨 선택 → 레벨 플레이 → 결과 확인 → 다음 레벨 또는 재도전으로 이어집니다. 컷신은 지도에서 따로 볼 수 있어 레벨 플레이와 재도전은 바로 시작할 수 있습니다.

### 직접 설계한 범위

- 마법과 대상의 상호작용, 레벨의 핵심 규칙을 정했습니다.
- 장치와 지형을 배치하고, 플레이어가 규칙을 익힐 순서와 동선을 설계했습니다.
- 체력·효과·도전 조건 등 데이터와 밸런스를 조정했습니다.
- 실제 플레이에서 조작, 퍼즐 전달, 피드백을 확인했습니다.
- 아트를 선정하고 구현·수정 요청을 직접 작성했습니다.

### 구현에서 확인할 수 있는 사례: 조준과 실제 결과 일치

플레이어가 본 조준 안내와 실제 마법 적용 결과가 일치해야 퍼즐의 규칙을 신뢰할 수 있습니다. 현재 프로젝트는 대상 판정, 조준선과 투사체 이동에 공통 장애물 판정 구조를 사용합니다.

벽에 막히면 조준 안내가 장애물에서 끝나고, 투사체도 벽 뒤의 대상에 마법을 적용하지 않습니다. 컨베이어에는 별도 조준 지점을 두어 바닥과 실제 가로막는 벽을 구분합니다.

이 사례는 기능의 유무뿐 아니라 플레이어가 예상한 결과와 실제 동작의 일치까지 확인해야 한다는 점을 보여 줍니다.

### 구현에서 확인할 수 있는 사례: 재도전과 진행 기록 분리

레벨에 다시 들어가면 지형·로봇·장치·체력·마법과 시도 중 기록을 초기화하고, 클리어와 별 달성 기록은 별도로 보존합니다. 다음 레벨 해금과 추가 별 도전을 구분해 기본 진행과 재도전 목표를 나눕니다.

레벨 선택 지도와 결과 화면은 이 규칙을 플레이어에게 전달하는 화면입니다. 지도에서는 다음 도전 지점, 잠금 여부와 목표를 확인할 수 있고 결과 화면에서는 달성 조건을 별로 보여 줍니다.

## 협업 흐름

### 1. 의도와 범위 결정

플레이어에게 어떤 경험을 줄지, 이번 작업에서 무엇을 만들지 직접 정합니다. 기능 이름만 쓰기보다 플레이어의 행동과 기대 결과를 함께 적습니다.

남길 내용: 기획 의도, 핵심 규칙, 대상 화면·레벨, 이번 작업 범위.

### 2. 프롬프트 작성

원하는 동작, 변경 조건과 유지할 조건을 구분해 요청합니다. 데이터나 화면이 연결되면 영향을 받는 부분도 함께 적습니다.

남길 내용: 입력 조건, 실행 동작, 결과 상태, 예외 상황과 완료 기준.

### 3. AI 구현과 수정

Claude를 활용해 요구사항에 따른 코드 구현과 수정을 진행합니다. 기획 문서와 포트폴리오 설명을 정리할 때는 ChatGPT를 활용하고, 효과음 제작에는 ElevenLabs Sounds를 활용합니다.

역할 기준: AI가 제시한 결과를 최종안으로 삼을지는 직접 판단합니다.

### 4. 직접 플레이

기능이 실행되는지와 함께 의도한 경험을 전달하는지 확인합니다. 조작, 화면 안내, 동선, 난이도와 반복 플레이를 직접 봅니다.

검수 질문: 규칙을 이해할 수 있는가, 예상한 결과가 나오는가, 다음 행동이 보이는가.

### 5. 데이터·밸런스·레벨 조정

플레이 결과를 바탕으로 수정 방향을 정합니다. 수치, 공간 배치, 피드백 중 무엇이 문제인지 나누고 다음 요청에 반영합니다.

남길 내용: 관찰한 상황, 바꿀 대상, 바꾸는 이유, 다시 확인할 조건.

### 6. 결과와 설명 연결

최신 화면과 기획 문서, 구현 내용을 함께 확인해 포트폴리오 설명을 맞춥니다. 이전 화면을 현재 화면처럼 제시하거나, 자동 테스트를 플레이 성과로 설명하지 않습니다.

남길 내용: 확인한 버전과 화면, 관련 문서, 확인한 항목과 남은 작업.

## 프롬프트 예시

아래 문장은 현재 게임 규칙을 바탕으로 재구성한 요청 예시입니다. 실제 사용한 대화 원문이나 프롬프트 기록은 아닙니다.

### World of Plant: 설치 예외 조건 전달

```text
목적: 다른 행성에 도착한 블루프린트의 설치 상태를 일관되게 보여 주기.
조건: 화물 도착과 건물 설치 완료를 서로 다른 상태로 처리한다.
예외: 설치에 필요한 에너지가 부족하면 대기 상태와 이유를 유지한다.
확인: 일부만 설치되거나 같은 비용이 중복으로 차감되지 않는지 확인한다.
보고: 수정 범위, 확인한 조건, 아직 확인하지 못한 조건을 구분한다.
```

이 예시의 핵심은 정상 동작만 설명하지 않고, 자원이 부족할 때의 상태와 재화 처리까지 요청에 넣는 것입니다.

### Wordless Mage: 조준과 충돌 기준 전달

```text
목적: 조준 안내와 실제 마법 적용 결과를 일치시키기.
조건: 대상 판정, 조준선, 투사체가 같은 장애물 판정을 사용한다.
예외: 대상 앞에 벽이 있으면 안내와 투사체가 벽에서 멈춘다.
예외: 트리거와 대상 자신의 콜라이더는 가로막는 벽으로 처리하지 않는다.
확인: 벽 뒤 대상에 효과가 적용되지 않는지, 컨베이어 바닥이 오판정되지 않는지 확인한다.
```

이 예시의 핵심은 화면 안내와 내부 판정을 별개 기능으로 끝내지 않고, 플레이어가 기대할 결과를 공통 기준으로 전달하는 것입니다.

### 효과음: 소리의 역할 전달

```text
상황: 플레이어가 행동 결과를 확인하는 짧은 피드백 효과음.
역할: 반복 입력음과 결과 확정음을 서로 구분할 수 있게 한다.
기준: 다른 소리와 겹쳐도 목적이 드러나고 반복 청취에 부담이 적어야 한다.
검수: 실제 게임 음량과 재생 빈도에서 들어 보고 채택 여부를 정한다.
```

도구에 음향 제작을 요청할 때도 분위기만 나열하기보다, 게임 안에서 어떤 정보를 전달하는 소리인지부터 정리합니다.

## 회고와 다음 단계

### 지원서에서 전하고 싶은 강점

기획을 문서로 설명하는 것과 함께 실제 게임으로 확인하려고 합니다. 컨셉과 핵심 규칙을 직접 정하고, AI가 구현할 수 있는 작업 조건으로 바꾸며, 플레이 결과를 바탕으로 데이터·밸런스·레벨을 조정했습니다.

두 프로젝트는 서로 다른 설계 관점을 보여 줍니다. World of Plant는 생산과 성장 구조의 연결을, Wordless Mage는 상호작용의 일관성과 공간을 통한 규칙 전달을 설명할 수 있는 결과물입니다.

### 계속 보강할 작업 기록

- 실제 프롬프트 원문과 해당 작업의 전·후 화면 한 쌍.
- 직접 관찰한 문제, 수정 지시, 다시 플레이한 결과를 연결한 사례.
- 직접 정한 수치와 조정 이유를 보여 주는 밸런스 표.
- 레벨 배치 의도와 플레이 동선을 표시한 이미지.
- 선정한 아트·효과음의 용도와 채택 이유.

위 항목은 앞으로 덧붙일 자료입니다. 확인되지 않은 개선율, 제작 시간 절감 수치, 사용자 지표는 기재하지 않았습니다.

### 기록을 남기는 형식

| 항목 | 작성할 내용 |
| --- | --- |
| 관찰 | 직접 플레이 중 확인한 구체적인 상황 |
| 판단 | 어떤 경험을 위해 무엇을 바꾸기로 했는지 |
| AI 요청 | 입력한 조건과 원하는 결과 |
| 결과 | 변경 화면 또는 재현 가능한 동작 |
| 재검수 | 직접 다시 확인한 내용과 남은 문제 |

한 사례를 이 순서로 연결하면 도구 사용 경험과 기획 판단을 함께 설명할 수 있습니다.
