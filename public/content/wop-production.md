# World of Plant 제작 과정

## 1. 반복할 행동과 성장 목표 정하기

처음에는 커서로 꽃을 깨워 자원을 얻고, 이후에는 장치와 자동화를 통해 더 큰 생산 구조를 만드는 흐름을 설계했습니다. 플레이어가 같은 행동을 반복하더라도 새로운 투자와 확장 목표를 찾도록 생산과 성장의 연결을 정했습니다.

### 직접 정한 것

- 커서의 파동, 식물의 생산, 자원 사용과 공간 확장의 관계.
- 손으로 시작한 생산이 장치·로봇·로켓으로 이어지는 방향.
- 식물과 장치가 함께 놓이는 공간에서 플레이어가 판단할 내용.

### 다음 작업으로 넘긴 기준

꽃을 깨우는 행동과 생산 결과가 화면에서 연결되어야 합니다. 자원을 얻은 뒤에는 무엇에 투자할 수 있는지 보이고, 투자 이후에는 생산 구조가 달라져야 합니다.

## 2. 규칙을 구현 요청으로 바꾸기

핵심 규칙을 정한 뒤에는 기능별 입력과 결과를 구분해 프롬프트로 전달했습니다. 생산, 설치, 업그레이드와 확장이 서로 연결되므로, 하나의 기능을 요청할 때 함께 영향을 받는 상태도 확인하는 방식입니다.

### 요청에 담는 내용

| 구분 | 확인할 내용 |
| --- | --- |
| 입력 | 어떤 도구를 선택하고 어디에 행동하는가 |
| 조건 | 배치 공간, 범위, 비용과 보유 자원이 맞는가 |
| 결과 | 무엇이 설치되고 어떤 생산 효과가 생기는가 |
| 예외 | 설치할 수 없거나 자원이 부족할 때 어떻게 알려 주는가 |

Claude는 요구사항에 따른 코드 구현과 수정을 돕고, 요청 내용과 결과를 받아들일지는 직접 판단했습니다.

## 3. 생산 구조와 배치 공간 만들기

식물과 장치는 생산 규칙만으로 완성되지 않습니다. 어떤 위치에 무엇을 놓을지 판단할 수 있도록 배치 공간과 확장 흐름을 함께 설계했습니다. 화면에서는 식물의 종류, 장치와 작동 범위, 현재 선택한 도구를 구분할 수 있어야 합니다.

### 직접 맡은 작업

- 식물과 장치의 배치, 생산 구조와 공간 확장 설계.
- 필요한 데이터와 효과, 비용·보상의 밸런스 조정.
- 게임 분위기와 기능 구분에 맞는 아트 선정.

### 플레이에서 보는 것

한 번 설치한 뒤 끝나는 공간이 아니라, 다음 투자에 따라 다시 손보고 확장할 수 있는 공간인지 확인합니다. 생산량과 함께 무엇이 어디에서 작동하는지 읽히는지도 봅니다.

## 4. 업그레이드와 자동화 연결하기

성장의 변화를 숫자와 화면 양쪽에서 느낄 수 있도록 업그레이드와 자동화를 연결했습니다. 자원을 어디에 투자할지 결정하고, 그 결과를 바탕으로 다음 배치와 확장을 생각하는 흐름입니다.

### 데이터·밸런스 조정의 관점

- 비용을 지불한 뒤 효과의 변화를 알아볼 수 있는가.
- 직접 조작과 자동화의 역할이 구분되는가.
- 한 기능만 반복하는 대신 다음 목표를 생각할 여지가 있는가.
- 새로운 생산 수단이 기존 배치와 어떤 관계를 만드는가.

수치와 조정 방향은 직접 결정했습니다. AI가 구현한 값이나 동작도 실제 플레이 결과를 보고 검토했습니다.

## 5. 행성 확장과 설치 상태 확인하기

현재 게임에는 다른 행성으로 화물과 블루프린트를 보내고 도착 뒤 설치를 진행하는 구조가 있습니다. 확장은 새로운 공간을 여는 것과 함께 생산 구조를 이어 가는 기능입니다.

### 상태를 나누어 확인하는 이유

| 상황 | 확인할 결과 |
| --- | --- |
| 화물 도착 | 자원과 설치 진행을 구분할 수 있어야 함 |
| 설치 가능 | 배치와 비용 처리가 일관되어야 함 |
| 에너지 부족 | 대기 상태와 부족한 이유가 유지되어야 함 |
| 다시 진행 | 일부 설치나 중복 차감 없이 이어져야 함 |

정상 동작과 예외 상황을 함께 살펴야 확장 이후에도 플레이 흐름이 이어집니다.

## 6. 직접 플레이하고 수정 방향 정하기

기능이 실행되는지와 함께 플레이어가 규칙을 이해하고 다음 행동을 선택할 수 있는지 직접 확인했습니다. 프롬프트 작성, 플레이 테스트, 데이터·밸런스 조정, 레벨디자인과 아트 선정은 모두 직접 맡았습니다.

### 검수 순서

1. 조작과 화면 안내를 확인합니다.
2. 설치·생산·투자 결과가 의도와 맞는지 봅니다.
3. 반복 플레이에서 흐름이 끊기는 지점을 확인합니다.
4. 수치, 배치, 피드백 중 바꿀 대상을 정합니다.
5. 수정 내용을 요청하고 다시 플레이합니다.

기획 의도를 정하는 일부터 결과를 판단하는 일까지 직접 이어 가고, AI는 구현과 수정 작업을 지원하는 방식으로 활용했습니다.
